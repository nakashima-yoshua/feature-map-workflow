パズルの登録と完成記録

架空のパズル記録帳「星の小箱」 · changedraft

Goal

Purpose:架空の利用者がパズルを記録し、未完成と完成済みを区別できるようにする。

Done:登録、重複拒否、完成への変更、完成済みへの再操作について、期待する動作を実装とテストで確認する。

Scope:パズルIDと名前の登録、一覧表示、完成への変更。名前は1〜40文字とする。

Exclude:アカウント、購入、決済、外部通信、他の利用者との共有、記録の削除。

Use Cases

UC-REGISTER:利用者が未登録のパズルを追加する。
Sample: PZ-001 / 月の迷路。どちらも架空の値。

UC-COMPLETE:利用者が登録済みのパズルを完成済みにする。
Sample: PZ-001を未完成から完成済みへ変更する。

Knowledge

  • ruleRULE-NAME:名前は1〜40文字とする。この仮想例では前後の空白を除去した後のUnicodeコードポイント数で数える。
  • ruleRULE-ID:IDが重複する登録は拒否し、既存の名前と状態を変更しない。
  • invariantINV-COUNT:完成操作によって記録件数は変わらない。
  • invariantINV-STATE:登録済みの記録の状態は未完成または完成済みのいずれかとする。
  • decisionDEC-REPEAT:完成済みに対する完成操作は成功として扱い、状態を維持する。(reason: 二度クリックしても利用者が同じ結果を確認できるようにするため。)
  • constraintCON-FICTION:全内容は説明用に創作したものであり、sourceMapは実装の存在やテスト成功を示さない。

Verify

ID Type Status Condition Expect / Observe
TEST-REGISTER normal planned 未登録のPZ-001と名前「月の迷路」を登録する。 未完成の記録が1件増える。
TEST-NAME boundary planned 未登録IDで、空白除去後の名前が0、1、40、41文字の各入力を試す。 1文字と40文字だけを受け付け、0文字と41文字では記録を追加しない。
TEST-DUPLICATE duplicate planned PZ-001を登録した後、同じIDで別の名前を登録する。 重複エラーとなり、元の名前、状態、件数を維持する。
TEST-COMPLETE state planned 未完成のPZ-001に完成操作を行う。 PZ-001だけが完成済みとなり、件数は変わらない。
TEST-REPEAT retry planned 完成済みのPZ-001に完成操作を再実行する。 成功として応答し、名前、状態、件数を維持する。

Open

  • OPEN-STORAGE [medium / environment]:記録の保存方式は未定。現在の例示では保存方式を前提にしない。→ この仮想システムを実装する場合に保存方式と再起動後の保持要否を決める。
  • OPEN-MISSING [medium / expected-behavior]:未登録IDに対する完成操作の応答は未定。→ 実装前に未登録IDへの完成操作の応答を決め、エラーケースを追加する。
